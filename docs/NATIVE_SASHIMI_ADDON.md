# Katana Native Sashimi Addon

Katana Native Sashimi is a dependency-light replacement path for `rmats2sashimiplot`.
It is designed around selected rMATS events rather than automatic bulk plotting.

## Repository Layout

This functionality is maintained in two forms:

- Standalone addon repository: `E:\Project\katana-native-sashimi`
- Embedded Katana integration: `src/adapters/native_sashimi_adapter.py`, `scripts/katana_native_sashimi.py`, and the Katana `5.5 Sashimi` UI

The standalone repository can be released or tested independently. The embedded Katana copy is the 1.0.1 integration layer so users can run the native sashimi workflow directly from Katana.

## Goals

- Run only user-selected splicing events.
- Use the same event table / manifest generated by Katana 5.5.
- Avoid the heavy Python dependency stack required by legacy `rmats2sashimiplot`.
- Make the figure easier to interpret: coverage, junction counts, PSI, dPSI, FDR and isoform structure are shown directly.
- Keep failures event-level so one failed event does not stop the whole batch.

## Inputs

The standalone CLI expects a TSV manifest with these core columns:

- `event_file`: one-row rMATS event TSV.
- `event_type`: `SE`, `RI`, `A3SS`, `A5SS`, or `MXE`.
- `event_uid`: stable event identifier.
- `geneSymbol` / `GeneID`: gene labels.
- `label1` / `label2`: displayed group labels.
- `b1_txt` / `b2_txt`: text files containing BAM paths for each group.
- `outdir`: output directory, relative to `06_sashimi/plots` unless absolute.

Optional but recommended columns:

- `dPSI`
- `FDR`
- `direction`
- `coordinates`
- `splicing_direction_flipped`

## Command Line

```powershell
python scripts\katana_native_sashimi.py `
  --manifest selected_manifest.tsv `
  --output-root katana_output `
  --gtf annotation.gtf `
  --samtools samtools
```

## Outputs

For each selected event, the addon writes:

- `native_summary.png/pdf/svg`: group-level mean sashimi-like plot.
- `native_replicates.png/pdf/svg`: replicate-level QC plot.
- `native_sashimi_junction_counts.tsv`: event-level junction counts per sample.
- `native_sashimi_psi_summary.tsv`: group PSI summaries.

Batch-level failures are written to:

- `06_sashimi/failed_native_sashimi.tsv`

## BAM Backend

Katana Native Sashimi uses `samtools` when it is available. On Windows, where bioconda does not provide a `samtools` package, it falls back to the pure-Python `bamnostic` reader.

Recommended Katana conda environment setup:

```powershell
conda run -n katana-splicing-tool python -m pip install bamnostic
```

If you do have a Windows `samtools.exe`, set it in `Settings -> samtools`.

## Current Scope

The first integrated version supports the five standard rMATS event classes:

- `SE`
- `RI`
- `A3SS`
- `A5SS`
- `MXE`

The plot uses rMATS coordinates and optional GTF annotation to build an event-level isoform model. If GTF is available, additional exons overlapping the event region can be drawn so multi-exon skipped regions are easier to interpret.

## Katana Integration

Inside Katana:

1. Open `5.5.2 Run Sashimi`.
2. Filter/search/sort events like an Excel table.
3. Multi-select events.
4. Click `Generate selected manifest`.
5. Choose `Katana native`.
6. Click `Run selected sashimi`.
7. Review plots and failed jobs in `5.5.3` / `5.5.4`.

Opening the page does not generate plots. Running native sashimi only loops over selected events.
