# Unified parameters and automatic cleanup — 28 October 2026

The storage-aware `katana-flow run` launcher accepts the native workflow's
public sample, comparison, reference, resource and analysis parameters, either
directly or through the same YAML/JSON parameter file. CLI values override the
file. Internal project/settings JSON is generated by the existing native
Nextflow configuration task. Advanced explicit configuration remains supported.

Complete mode consumes that task's published configuration for import and the
downstream stage. Successful upstream cleanup does not remove this published
configuration. Existing-project mode generates its downstream settings through
the native workflow without scheduling upstream analysis.

The publication/cleanup policy is unchanged: retain the scientific outputs,
portable project and report; remove only registered successful stage work.
Failure preserves the affected work. `--keep-work`, later explicit cleanup and
resume retain their existing semantics. Direct `nextflow run` still retains
work and uses its normal `-work-dir`; the managed launcher uses `--run-dir`.

## Observed validation

- The focused Windows suite passed 89 checks with two symlink-privilege skips.
  Two additional configuration-tamper/keep-work cases then passed in the final
  15-case unified-entry suite. No scientific calculation was repeated.
- Real Nextflow 25.10.4 ran the actual configuration process, published its
  files, and ended successfully. After actual upstream-work deletion, a second
  native session consumed the published settings successfully. Both owned
  work directories were removed; configuration and source inputs remained.
- The upstream source verifier passed: 89 preserved files and 37 declared
  integration changes. Upstream scientific modules were not modified.
- A locally built wheel was installed into an isolated target directory.
  Public command help, direct parameter parsing and exported parameter-schema
  equality passed outside the source checkout. This reused existing Python
  dependencies; it is not a new complete Conda/container qualification.
- The native handoff check is included in GitHub's Nextflow integration job.
  Remote CI status is separate from these local observations.

These are configuration, lifecycle, retention and packaging checks with
generated protocol data. They do not claim a new biological FASTQ/BAM run,
Slurm execution, container rebuild or report-format change. The approved report
renderer, algorithms, defaults and completed study results remain unchanged.
